## `popover-placement` — DONE 2026-09-19

**The help elements are in the same coordinate system as the node boxes.** The
popover mounts inside the canvas's zoom wrapper, scales and pans with the
boxes, and is out of the top layer. `make e2e` 5/5, from 2 pass / 3 fail.

What shipped, against the plan that was in BACKLOG §Placement:

- **Popover inside the zoom transform**, portalled into the wrapper. The host
  registers the wrapper as a mount SCOPE and the package walks up from the
  anchor element to find it ([mountPoints.ts](../../src/help/mountPoints.ts)) —
  so `src/help/` still knows nothing about canvases. Per-popover, not
  per-application: a step anchored outside the canvas gets body level, as
  before.
- **Out of the top layer.** `popover="manual"` / `showPopover()` are gone; the
  open state is `[data-open]`. Clipping to the canvas is correct now that the
  popover lives there.
- **The zoom-linked font code is DELETED**, which the plan made the acceptance
  check rather than a side-benefit. The popover scales with the boxes on its
  own, so `helpTheme.css` holds a constant 16px.
- **`PAN_SLACK` 0.5 → 0.25.** Siggie's conjecture confirmed: half its purpose
  was reaching popover tops. The other half — recovering a box dragged off the
  edge — is why it is not zero.

⚠️ **The cause was not any of the three things proposed for it**, including the
one written into the plan. It was that `position-area` places within the
CONTAINING BLOCK, and the wrapper was sized exactly to the content, so a
popover anchored on the lowest box had nowhere below it to go. `HELP_ROOM` in
[useZoomPan.ts](../../src/explore/graph-core/useZoomPan.ts) is the fix. The
falsified causes are in WORKLOG (2026-09-19 evening) — read them before
re-proposing one.

⚠️ **Leaving the top layer made the spotlight scrim dim the popover**, which
nothing predicted: the top layer had been keeping them apart. The scrim colour
is now a knob (`--help-scrim`) and dmvd dims its own node boxes instead
(Siggie: *"try just dimming the unselected node boxes instead of the whole
viewport"*). That dimming CANNOT live in CSS — see WORKLOG.
